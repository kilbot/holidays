# Link-as-permission sharing, no accounts

The site has exactly two real users (the couple) plus casual friend-visitors, privacy is explicitly not a concern, and time-to-ship matters (booking deadlines land ~1 Oct 2026). We therefore have no accounts and no auth system: **holding a URL is the permission**. The canonical Plan has two links — a view link shared freely and an edit link held by the couple; every visitor Fork is a named, saved Scenario with its own URL that its creator edits by holding the link. Forks can never modify the canonical Plan; the couple can adopt (copy) a fork into their Scenario list. The rejected alternative — login/co-editing — adds an auth system for an audience of two and creates the drunk-mate-reorders-the-itinerary failure mode; the accepted trade-off is that anyone who obtains the edit link can edit, which for this audience is fine. Note the repo is public: the edit link must live in deployment env/data, never committed here.

## Storage (decided in #30)

**Upstash Redis**, via the Vercel Marketplace integration, which injects `KV_REST_API_URL` and `KV_REST_API_TOKEN` — no new environment variables of our own. Three keys: `plan:<planId>` is the canonical Plan document, `plan:<planId>:meta` holds `{ editKey }` on its own so the view route cannot leak it, and `fork:<forkId>` is one visitor's saved `PlanInput`. Postgres was the alternative and would have bought querying, relations and migrations, none of which a site with one row per concept and no listing screen has any use for. Ids are 16 base58 characters from `crypto.getRandomValues` — unguessable is the entire access-control mechanism, so they are generated the same way for plans, edit keys and forks.

The plan id is **not** a secret: it is the view link, and it lives in `lib/store/canonical-plan.ts` as a constant, because this site has exactly one Plan and a route parameter nobody ever varies is not configuration. The edit key exists in exactly two places — Redis, and whatever the couple bookmarked. `scripts/bootstrap-plan.mjs` refuses to print it to a terminal and writes it to a file the operator names, so it never reaches scrollback, CI logs or an agent transcript.

The edit key travels in an `x-southbound-edit-key` header and arrives in the browser as a `#edit=` URL **fragment**, once: fragments are never sent to a server, so the key appears in no access log and no `Referer`, and the client strips it out of the address bar as soon as it has been stored. Writes are additionally capped at 100 KB and throttled to 20 per minute per IP against the same Redis — not security, which the ADR above deliberately does not have, but the difference between a public endpoint and a public endpoint that can be turned into a bill.
